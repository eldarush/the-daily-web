# החלק של שגב — מדריך קצר להגנה

## מה מימשתי

פיד חדשות ציבורי עם טעינה ראשונית של 20 כתבות, גלילה לטעינת 20 נוספות,
חיפוש בכותרת ובתקציר, סינון קטגוריה ונצפה/לא נצפה, ומיון לפי תאריך או צפיות.
כל הפעולות האינטראקטיביות מתבצעות באמצעות Ajax ללא רענון העמוד.
נעשה שימוש רק במחסנית הקיימת: Express, Mongoose, EJS, JavaScript רגיל ו־CSS Flexbox.
לא נוספו חבילות ל־package.json.

## מי עושה מה

| קובץ | התפקיד שלו |
|---|---|
| `controllers/feedController.js` | בודק את הפרמטרים, בונה שאילתה, שולף נתונים ומחזיר JSON או עמוד EJS |
| `routes/api/feedRoutes.js` | מחבר בקשות API לפונקציית השליפה |
| `routes/webRoutes.js` | מחבר את `/` לרינדור עמוד הבית |
| `views/pages/home.ejs` | מבנה העמוד, מסננים, מונה, רשימת כתבות והודעות |
| `views/partials/feed-card.ejs` | מבנה של כרטיס אחד; משמש גם ל־SSR וגם לתבנית הכרטיסים בדפדפן |
| `public/js/newsfeed.js` | שולח בקשות, מצייר כרטיסים, מנהל גלילה ושומר היסטוריית קריאה |
| `public/css/newsfeed.css` | פריסת Flexbox, צבעים והתאמה למסכים קטנים |

`app.js` רק מחבר את הנתיבים. השינוי במודל `Article` מוסיף אינדקסים למיון
הפיד, והשינוי ב־footer טוען את הסקריפט גם בעמוד כתבה לצורך מעקב קריאה.

## זרימת הבקשה

1. כניסה ל־`/` מפעילה את `renderHome`.
2. `loadFeed` בונה סינון שמתחיל תמיד ב־`status: 'published'`.
3. החיפוש, הקטגוריה והיסטוריית הקריאה מצטרפים לסינון לפני החלוקה לעמודים.
4. `sort` קובע את הסדר; `skip` מדלג על העמודים הקודמים ו־`limit(20)` מגביל את המנה.
5. `populate` מוסיף את שם הכתב, ו־`select` מצמצם את התוצאה לשדות ציבוריים.
6. EJS מחזיר את 20 הכרטיסים הראשונים כבר ב־HTML.
7. שינוי מסנן מפעיל `fetch`, וה־JavaScript מחליף את הכרטיסים בלבד.
8. התקרבות לסוף מפעילה `IntersectionObserver`, שמבקש את העמוד הבא ומוסיף כרטיסים.

## שאלות שכדאי לדעת להסביר

**למה מגבילים ל־20 בשרת?** גם אם משנים את הבקשה ידנית, הלקוח לא קובע את גודל המנה.
העמוד האחרון מכיל רק את הכתבות שנותרו.

**מה עושה `hasMore`?** משווה את מספר הכתבות עד סוף העמוד למספר התוצאות הכולל.
אם יש עוד תוצאות, מותר לבקש עמוד נוסף.

**למה `_id` נמצא במיון?** לשתי כתבות יכולים להיות אותו תאריך ואותה כמות צפיות.
המזהה שובר את השוויון, כדי שהסדר לא יהיה שרירותי בין בקשות.
פרסום כתבות חדשות ושינויים בצפיות בזמן הגלילה עדיין יכולים להזיז תוצאות במיון מבוסס עמודים.

**למה חיפוש כולל השהיה של 300 מילישניות?** `setTimeout` ו־`clearTimeout`
מונעים בקשת שרת חדשה על כל אות שהמשתמש מקליד מהר.

**למה מנקים תווים מיוחדים מהחיפוש?** החיפוש צריך למצוא טקסט כמו `[sport]`
כפי שהוקלד, בלי לפרש אותו כביטוי רגולרי שמשנה את השאילתה.

**איך מונעים חשיפת טיוטה?** מסננים כתבות מפורסמות בלבד ובוחרים במפורש את שדות
הכרטיס. לא מחזירים `pendingUpdate`, הערות עורך או את גוף הכתבה המלא.

**איך יודעים אם כתבה נקראה?** בעמוד כתבה שומרים את המזהה במערך `localStorage`.
בפיד קוראים את המערך ושולחים את המזהים לצורך `$in` או `$nin` לפני הדפדוף.
ההיסטוריה שייכת לדפדפן הזה. היא אינה הרשאה ואינה מסתנכרנת למחשב אחר.
אם האחסון חסום, אפשר לקרוא ולסנן חדשות, אבל היסטוריית הקריאה לא נשמרת.

**למה יש גם POST לחיפוש?** אלפי מזהים בכתובת GET יכולים לעבור את מגבלת HTTP.
בסינון קריאה שולחים את הפרמטרים בגוף JSON ל־`/api/articles/search`.
זהו אותו חיפוש לקריאה בלבד, ללא שינוי כתבות. GET נשאר לפיד הרגיל ולפרמטרים קצרים.

**איך מונעים תשובה ישנה אחרי החלפת מסנן?** כל בקשה מקבלת מספר.
רק הבקשה האחרונה רשאית לעדכן את התצוגה ואת מצב הטעינה.

**מה קורה כשבקשת עמוד נכשלת?** מספר העמוד מתקדם רק לאחר הצלחה.
כפתור Retry מנסה את אותו עמוד, בלי לדלג על כתבות.

**למה לא משתמשים ב־innerHTML לטקסט של כתבה?** כדי שכותרת המכילה תגיות תוצג כטקסט
ולא תרוץ כקוד. ב־EJS משתמשים ב־`<%=` וב־JavaScript ב־`textContent`.

## מה לבדוק בהדגמה

- גלילה עד טעינת מנה נוספת ומנה אחרונה קצרה.
- שילוב חיפוש, קטגוריה, מיון ומצב קריאה; בלי רענון העמוד.
- טיוטה ועדכון ממתין אינם מופיעים בפיד.
- כניסה לכתבה, חזרה לפיד ובחירת Read only, לאחר שילוב החלק של אופיר.
- תצוגת מובייל, חיפוש ללא תוצאות וניתוק רשת עם Retry.

הוראות הרצה ובדיקות נמצאות ב־README. בדיקות הדפדפן משתמשות במסד בדיקה ריק ונפרד.
בדיקת עמוד הכתבה מדמה את מבנה העמוד של אופיר; היא לא מחליפה בדיקת אינטגרציה אמיתית.

## ממצאים בקוד הקיים של הקבוצה

אלה ממצאים לבדיקה משותפת, שלא תוקנו בחלק של שגב:

- במצב הנוכחי אין ב־master עמוד `/articles/:id` או מודול תגובות של אופיר.
  קישורי הפיד מוכנים לנתיב שסוכם, אבל העמוד המלא דורש את החלק שלו.
- `submitArticle` של הכתב דוחה כתבה במצב `published`, אף שניתן לשמור לה
  `pendingUpdate`. צריך להשלים את מחזור הגשה ואישור של עדכון מפורסם תוך שמירת הגרסה לציבור.
- שירות מזג האוויר מחזיר נתונים קבועים כשאין מפתח או כשהשירות נכשל,
  והווידג'ט יכול להציג אותם כעדכון חי. נתונים כאלה אינם מדידה עדכנית כנדרש.
- כאשר מטמון מזג האוויר פג, בקשות מקבילות יכולות לבצע כמה פניות לשירות החיצוני.
  יש לבדוק איחוד של פניות מקבילות לפני הדגמת עומס.

מעבר בדיקות המודול אינו אישור לכך שהמערכת כולה כבר עומדת בכל דרישות הפרויקט.
